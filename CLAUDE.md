# Rules for AI agents working in this repo

Warsaw Model Trainers hackathon (Kolektyw3, 25–27.09.2026), team Vibers.

- Never call the organizers' backend directly: no requests to `*.supabase.co`, the `mh_*` tables/RPCs or the question-upload form. Practice questions come only from `k3exam.py` output and the public run view in a browser. Trying to obtain the final sheet = disqualification.
- Never commit copyrighted material: CKE PDFs and anything derived from them stay in `data_cke/` and `devset/cke-*.jsonl` (git-ignored). Commit URL lists and scripts instead.
- `SOURCE.md` must keep exactly: `Made during the Warsaw Model Trainers hackathon, Kolektyw3, 25–27.09.2026` (en dash).
- Model limit (organizers, Telegram 26.09 + opening deck): 8 GB total weight size of the BASE model, any parameter count, quantization allowed, measured without the LoRA adapter and before our work; the final submitted model after our work may exceed 8 GB. TEAM DECISION (26.09): exactly ONE main LLM answers the whole exam — Bielik-4.5B-v3 (+ our LoRA). No helper/ensemble LLMs for answering, essays or voting. Auxiliary retrieval models (embedder bge-m3, reranker bge-reranker-v2-m3) are fine. CLARIFIED (26.09 ~21:45, team lead, from the organizers): any number of models may be used at exam time as long as EACH model is <= 8 GB on its own (Bielik Q8 5.06 GB, Qwen3.5-9B Q5_K_M + mmproj 7.50 GB: both fine). UPDATE (26.09 ~17:05, team lead): add ONE open vision model (<= 8 GB, runs offline) whose ONLY job is to describe the exam images (maps, photos, cartoons, posters) as Polish text; Bielik then works on text only and never sees images. No OCR in the final pipeline. The vision model must not answer the questions. The harness must not touch the internet during the test. Team policy: use every gain that does not break the rules and disclose it (README/presentation); grey-zone tricks (e.g. heavily quantized base vs high-precision final of the same model) only after explicit organizer confirmation.
- Never modify, re-save or re-quantize the registered base GGUF; the app checks its checksum. Run the base benchmark from a separate llama-server with no LoRA.
- Team decision: all generated datasets, benchmarks and questions come ONLY from Claude models (no other AI generators). To stay within Anthropic's output-use policy (specialised tools allowed, competing general models not), training targets are only short canonical answers grounded in the source text ("B", "P, F, P", "C, A, D, B", "1-B, 2-A", a name/year) — never Claude-written explanations or free-form prose. Official CKE items are human-made and may be used (transcribed by Claude).
- Dev sets (`devset/`) are evaluation-only; never train on them.
- Line endings are LF (`.gitattributes`); write remote shell scripts from Git Bash, not PowerShell.
- Panel ownership (from Sat 26.09 ~11:00): the web panel is edited by a teammate directly on the Mac in `~/wmt-matura/panel/`. That copy is the source of truth. Lead agents must NOT sync `panel/` from the laptop to the Mac; to update the laptop repo, copy Mac -> laptop. The panel only reads data (`devset/experiments.csv`, `devset/runs/`, `devset/sweep_results*.md`, `logs/`, `models/`); other agents may keep appending to those files.
- Mac memory budget (36 GB, shared; it froze twice on 26.09 from swap exhaustion): at most ONE LLM llama-server at a time on the Mac (plus the reranker and the panel). Before starting a model, check `sysctl vm.swapusage` and free memory; if swap is above 50%, do not start anything. Heavy or parallel runs (11B/12B models, several model instances, sweeps) go to the L40S. Stopping a workflow does NOT stop the processes it started: kill your own llama-server/python processes before you finish. On the L40S (30 GB container RAM, shared with training) every llama-server needs `--cache-ram 0` (or a small value); the default 8 GiB prompt cache got a server OOM-killed on 26.09.
- When you append rows to the Mac's `~/wmt-matura/devset/experiments.csv` from another machine (L40S), ALWAYS copy the matching per-question run files (`run_file` column) into `~/wmt-matura/devset/runs/` too; otherwise the panel shows "brak pliku" (reported by the panel owner's agent, 26.09).
